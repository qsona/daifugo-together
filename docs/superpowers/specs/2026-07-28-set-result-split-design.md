# 最終戦リザルトとセットリザルトの分離 — 設計

作成: 2026-07-28

## 背景

セットの最終戦（第3戦）が終わると、サーバーは `interimResult` を挟まずに `setResult` フェーズへ進む（`packages/core` のセット進行）。そのためクライアントも最終戦のゲーム結果を出さずに直接セットリザルト画面へ飛び、「第3戦がどうだったか」と「セット全体の勝者は誰か」が1画面に混ざっている。

## 目的

1. 最終戦のゲーム結果と、セットの総合結果を別々の画面に分ける。
2. セットリザルトに特別感を持たせる（1位の強調、紙吹雪）。
3. ゲームごとの順位点／順位と、セットの合計点／順位の見せ方を整理する（マリオカートの「レース結果 → カップ総合成績」の2段構えを参考）。

## 動線

### オンライン

```
第3戦 終了（room.phase: playing → setResult）
   ↓
[最終戦リザルト]  1・2戦目のゲーム間リザルトと同じ体裁
   ↓  10秒のカウントダウン、または「セット結果へ」をタップ
[セットリザルト]  表彰の特別画面 + 評価 + CTA
```

- 最終戦リザルトはクライアント内だけの表示段階。サーバーのフェーズ遷移・タイマー・継続応答（`respondBy`、既定120秒）の仕様は変更しない。10秒はその応答時間から差し引かれるだけで、進行を止めない。
- 同じセットで最終戦リザルトを通るのは一度だけ。`${roomId}:${setResult.respondBy}`（`packages/web/src/tutorial/graduation.ts` と同じセット識別のしかた）を「見た」印として保持し、`sync` や再接続で画面が巻き戻らないようにする。ページを再読み込みした場合は状態が失われるため、もう一度最終戦リザルトから始まる。これは許容する。
- 1・2戦目のゲーム間リザルトは現状のまま（サーバーの intermission、既定15秒）。

### ローカル見本フロー

`packages/web/src/store/screen.ts` の `gameResult` → `setResult` はすでに2枚構成なので、遷移は変えない。デモデータを「第3戦 おわり」「セット 3 / 3 戦」「セット結果へ」に合わせて更新する。

## データ

`SetResultView`（`packages/core/src/protocol.ts`）に最終戦の結果を追加する。

```ts
finalGame: {
  standings: { memberId: string; rank: number; title: string; points: number }[];
} | null;
```

- `points` はその戦で得た順位点（5-3-2-1）。
- 組み立ては `packages/server/src/room/view.ts` の `setResultView`。`engine.results.at(-1)` と `POINTS_BY_STANDING` / `TITLE_BY_STANDING` から作る。
- 最終戦の結果が揃っていない中断セット（`engine.results.length < engine.config.gamesPerSet`）と、結果が1件もない場合は `null`。

クライアント側で `standings[].ranks` から復元しない理由:

- `ranks` は該当プレイヤーの結果が見つからないとき `4` で埋める実装のため、離脱者が出たセットで最終戦の実データにならない。
- 順位点表（`packages/core/src/set/scoring.ts` の `POINTS_BY_STANDING`）を UI 側に複製したくない。

既存の `standings[].ranks` は、セットリザルトから順位推移の表示を外すことで未使用になる。protocol からは削除せず残す（他の利用余地があり、削除は本件の目的ではない）。

## 画面仕様

### 5a' 最終戦リザルト

既存の `GameResultScreen` をそのまま使い、渡す文言だけ変える。

| props | 値 |
| --- | --- |
| `title` | `第3戦 おわり`（`gamesPerSet` に追従した戦数） |
| `progressLabel` | `セット 3 / 3 戦` |
| `nextLabel` | `セット結果へ` |
| `autoAdvanceMs` | `10_000`（クライアント定数） |
| `autoAdvanceAt` | 最初の描画時に決めたローカル期限 |

行の読み順はマリオカートのレース結果と同じく **順位 → 称号 → 獲得順位点（+5）→ 合計点**。獲得点が乗ってから合計点がカウントアップする短い演出を入れる。ここでの合計点はセットの現時点合計で、最終戦なのでセットの最終合計と一致する。

### 5b セットリザルト

- 1位は大きな花形カード。内容は `1位` / 称号（大富豪）/ 名前 / 合計点。
- 2〜4位は1行ずつ。**順位・名前・合計点のみ**。現行の順位推移（`1→2→1`）は表示しない。各戦の結果は直前の最終戦リザルトで見せているため。
- 評価UI（おもしろかった？／発動したルールの評価）と CTA（もう1セットあそぶ／みんなのルールで あそんでみる／ホームへ）は現状のまま下に続く。

## 演出

| 状況 | 演出 |
| --- | --- |
| 自分が1位 | 紙吹雪（数秒で止まる）＋ 1位カードのポップイン |
| 自分が1位以外 | 紙吹雪なし。自分の行がひと弾みするだけ |
| 最終戦リザルト | 獲得順位点のバッジ表示 → 合計点のカウントアップ |

`prefers-reduced-motion: reduce` では紙吹雪を描画せず、カウントアップも最終値を即表示する（`packages/web/src/components` の既存部品と同じ扱い）。紙吹雪は装飾なので支援技術には露出しない（`aria-hidden`）。

## コンポーネント分割

現在の `RankRow` は2画面ぶんの表示条件（`history` / `gainedPoints` / `totalPoints` の有無）を1つの view-model で背負っている。今回の変更で両者の形がさらに離れるため分割する。

- `components/GameRankRows.tsx` — 順位・名前・称号・獲得順位点・合計点。最終戦リザルトとゲーム間リザルトで共用。
- `components/SetRankRows.tsx` — 1位の花形カード + 2〜4位の行。合計点のみ。
- `components/Confetti.tsx` — CSS keyframes だけの紙吹雪。DOM は20要素程度、`prefers-reduced-motion` で無効。

`RankRow.tsx` は上記2つに置き換えて削除する。呼び出し元は `GameResultScreen` / `SetResultScreen` の2つのみ。

`App.tsx` に足すのは「最終戦リザルトを見たセットの識別子」の状態と、`visibleSetResultRoom` の手前で最終戦リザルトを返す分岐だけに留める。

## エッジケース

| 状況 | 挙動 |
| --- | --- |
| `finalGame` が `null`（中断セット） | 最終戦リザルトを飛ばして直接セットリザルト |
| 最終戦リザルト表示中に再接続・`sync` | 画面は巻き戻らない（見た印で判定） |
| 表示中にページ再読み込み | 最終戦リザルトからやり直す。許容する |
| 卒業導線（`graduationFrom` のスナップショット表示） | セットリザルトのみ。最終戦リザルトは通過済み |
| 継続応答の期限が最終戦リザルト表示中に切れる | 現行と同じくサーバーのタイムアウト処理に従う |

## テスト

- server: `setResultView` が完走セットで `finalGame` を返し、中断セットで `null` を返すこと。
- web `App.test.tsx`: `setResult` フェーズに入ったとき最終戦リザルトが先に出て、次にセットリザルトへ進むこと。`sync` で巻き戻らないこと。`finalGame` が `null` なら最終戦リザルトを飛ばすこと。
- web `SetResultScreen.test.tsx`: 自分が1位のとき紙吹雪が出て、1位以外では出ないこと。順位推移が表示されないこと。
- web: 最終戦リザルトの行が順位・称号・獲得順位点・合計点を出すこと。

## やらないこと

- サーバーのフェーズ・タイマー仕様の変更（最終戦のあとに `interimResult` を挟む案は採らない）。
- 各戦の順位点の内訳をセットリザルトに表で出すこと（積み上げバー案・スコア表案はいずれも不採用。セットリザルトは合計点だけ）。
- ゲーム間リザルト（1・2戦目）の動線変更。
