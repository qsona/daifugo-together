## 1. 目的

**開発者の Critical (1)(2) をこのフェーズだけで解消する。**

- (1) ログインされているかどうかわからない → メニュー最上部の**アカウント行**が、なまえと状態バッジを常時出す(N-1・N-6・U-5)
- (2) ログアウト・アカウント切替の動線がない → **アカウント画面**を新設し、「Googleでつなぐ」「別のアカウントにする」「サインアウト」を置く(N-2・U-1)

副次的に J1-1・J1-2・J6-1(切替確認が到達不能コードだった)・J6-2(無確認 1 タップのログアウト)・J6-3(`window.confirm`)・J8-1(自分のなまえが見えない)が閉じる。

## 3. やること

### 3.1 新規部品 `AccountRow`(A-1〜A-6)

`packages/web/src/components/AccountRow.tsx`(+ `.module.css`)を新規作成する。

- **1 つのボタン**。押すとアカウント画面へ行くだけで、**アカウント操作は絶対に起こさない**(J6-2 を構造的に潰す)
- 中身は左から **なまえ / 状態バッジ / シェブロン(›)**。ラベル(「なまえ:」)は置かない(原則 2)
- props(想定): `displayName: string | null` / `state: 'anonymous' | 'registered' | 'pending' | 'connecting'` / `isDefaultName: boolean` / `onOpen: () => void`
- **既定名(`ゲスト######`)のときは控えめな未設定スタイル**(細字・淡色)にする(A-1・Q-6 = B)。催促文やバナーは置かない
- `pending`(`authPending`)・`connecting`(`connection !== 'ready'`)は `disabled` にし、バッジを差し替える。なまえが未取得のときは **`—` で高さを保つ**(行ごと消さない。A-5)
- 既定名かどうかの判定は**サーバーの既定名生成規則**(`packages/server/src/persistence.ts:85-92`。`ゲスト` + 連番を base36 で大文字化しゼロ詰めした 6 桁)に対応する正規表現で行い、判定関数はテスト可能な形で切り出す

状態とバッジの対応(ワイヤー §2「状態バッジ」・A-1〜A-6):

| 状態 | バッジ | 見た目 |
|---|---|---|
| 未登録 | **この端末だけ** | 通常のタグ |
| 登録済み | **どの端末でも** | 塗りタグ |
| 処理中(`authPending`) | **つなぎ中** | 行全体を淡色 + `disabled` |
| 接続未確立 | **接続中** | 同上。なまえは `—` |

`Tag` には現在アカウント用の `variant` が無い(local / original / active / removed / human / ai の 6 種)ので、**中立系と塗り系を 1 つずつ追加する**。追加したら `docs/design/design-system.html` に見本を足す(デザインシステム §5)。

### 3.2 メニューへの組み込み(A-1〜A-4・A-6)

`packages/web/src/screens/MenuScreen.tsx` / `MenuScreen.module.css`。

- 最上部を **`[アカウント行][通知ベル]` の 1 行**にする。`.notification`(現状 `justify-content: flex-end` の独立行)を `display:flex` の横並びに変え、アカウント行を `flex:1` にする。**ベルはアカウント行の外**に置く — 行全体が 1 つのボタンなので中にボタンを入れ子にできない
- **廃止D-1**: `MenuScreen.tsx:70-78` の「登録済み・ログアウト」/「引き継ぎ・ログイン」小ボタンを削除する。`registered` / `onLogin` / `onLogout` / `authPending` の props もこの画面からは外し、代わりに `AccountRow` に必要な props(なまえ・状態・`onOpenAccount`)を受け取る
- `authMessage` の裸の `<p role="status">`(`MenuScreen.tsx:79`)は**このフェーズでは残す**(受け皿を作るのは 2/5)。ただし表示位置は変えない
- 導線は現行のまま(あそぶ / ルールを提案する / ルール図鑑 / マイ提案)。マイ提案の未読バッジもそのまま

### 3.3 新規画面 `AccountScreen`(B-1・B-2)

`packages/web/src/screens/AccountScreen.tsx`(+ `.module.css`)。ルーティングに `account`(パス `/account`)を追加する(`store/screen.ts` の `ScreenId`、`routing.ts` の `SCREEN_PATHS`)。

構成(上から):

1. `AppBar` タイトル **「記録」**、戻るはメニューへ
2. なまえ(大きめ・太字)。**「なまえを変える」ボタンはこのフェーズでは出さない**(遷移先の C-1 が 4/5 だから。押せない・何も起きないボタンを画面に置かない)。ワイヤー B-1 / B-2 の当該ボタンは 4/5 で足す。`AccountScreen` にその旨のコメントを 1 行残す
3. 記録の中身のボックス: **「提案 3件」**+ 小ボタン「見る」(マイ提案へ)、その下に **「イエローカード 0枚」**
   - 取得元は既存の `ProposalClient`(`proposal/client.ts`)の **`mine()`**(`GET /api/proposals/mine`)と **`getYellowCards()`**(`GET /api/me/yellow-cards`)。どちらも読み取り系で匿名でも通る。新しい API クライアントは作らない
   - **props で受け取る `api` は部分型にし、`mine` / `getYellowCards` が未定義でも落ちないようにする**(既存画面が `Pick<...>` で最小の API を受け取っている流儀に合わせる。テストのモックが取りこぼしたときに画面ごと落ちるのを防ぐ)。未定義なら件数は `—` のまま
   - **取得中・取得失敗はどちらも数字の位置を `—` にして行の高さを保つ**。スピナーは置かない。画面のエラーとして扱わない
   - **件数の取得完了を待って認証操作を止めない**
4. 状態タグ(押せない):未登録 = **「記録はこの端末だけ」** / 登録済み = **「Googleでつないである・どの端末でも」**
5. 操作
   - 未登録: primary **「Googleでつなぐ」** → DLG-1
   - 登録済み: **「別のアカウントにする」** → DLG-2、**「サインアウト」** → DLG-3。どちらも画面最下部に置き、上の主要領域と距離を取る

**接続未確立のとき(A-5)**: `connection !== 'ready'` では「Googleでつなぐ」「別のアカウントにする」を**押せない状態にし**、理由の 1 行を**無効化されたボタンの下流**に置く(「サーバーとつながるまで待ってください」)。現状は押してから初めてメッセージが出る(`beginLogin` の「接続を確認しています。少し待ってから、もう一度ためしてください。」)。**押す前に形で伝える**のが A-5 の要点(原則 3)。`beginLogin` 側の同メッセージは保険として残してよい。

**この画面に説明文を置かない**(`Callout` は 0 枚)。「Googleでつなぐと…」の解説は押した**あと**の DLG-1 の中にある(原則 1 の位置テスト)。

### 3.4 確認ダイアログ 3 種

**3 つとも `App.tsx` に状態を持ち、ルート直下(画面の return より外側)に描画する。**とくに **DLG-1 は最初からルート直下に置く** — 3/5 で提案画面・退室後の誘いからも同じダイアログを開くことになり、アカウント画面の中に閉じ込めると開けなくなるため。開く要求は「どの画面からでも `openConnectDialog()` を呼べば出る」形にしておく。

**DLG-1「Googleでつなぐ」**(`Dialog` + `DialogBody`。**非破壊なので primary は実行側**)

```
見出し: Googleでつなぎますか?
本文1 : ほかの端末でも、同じなまえ・同じ提案であそべるようになります。
本文2 : Googleの画面に移りますが、受け取るのはIDだけで、終わったらここにもどります。
実行  : Googleへ進む   (処理中は「Googleへ進んでいます」+ disabled)
取消  : もどる         (CONFIRM_BACK_LABEL)
```

- 押下で既存の `beginLogin` を呼ぶ。**このダイアログが認証実行の唯一の入口**になる(3/5 で他経路からもここを開く)
- なまえの確認枠は 4/5 で足す。本文 2 文はこのまま
- `beginLogin` 内の `window.confirm`(`817409b` 時点で `App.tsx:717-723`。レビューの `:709-713` はコミット時点の行)は DLG-2 へ移すので、**`beginLogin` から確認処理を取り除く**(下記 3.5)

**DLG-2「別のアカウントにする」**(`ConfirmDialog`。**primary は取り消し側**)

```
見出し    : 別のアカウントにしますか?
description: この端末は、えらんだGoogleアカウントの記録に切り替わります。今の「{なまえ}」の記録は消えず、また同じGoogleでつなげばもどってきます。
実行      : Googleへ進む
取消      : もどる (CONFIRM_BACK_LABEL)
```

- `ConfirmDialog` の `description` は 1 つなので 2 文を連結して渡す。改行が要るなら `Dialog` + `DialogBody` 2 つに替えてよい(見出しと primary の規範は同じに保つこと)
- **この文言は登録済みユーザー専用**。未登録が DLG-1 から `switched` になった場合は事情が逆なので、同じ文言を使い回さない(そちらは 2/5 の RES-2 S-a)

**DLG-3「サインアウト」**(`ConfirmDialog`。**primary は取り消し側**)

```
見出し    : サインアウトしますか?
description: この端末から記録が離れて、新しいゲストになります。記録は消えず、またGoogleでつなげばもどってきます。
補足(条件付き): この端末のおしらせも届かなくなります。
実行      : サインアウトする
取消      : もどる (CONFIRM_BACK_LABEL)
```

- **補足の 1 文は、この端末で通知を購読している人にだけ出す**(原則 4。常設しない)。判定は `registration.pushManager.getSubscription()` による**非同期取得でよい** — ダイアログを開いた時点で問い合わせ、判明したら 1 文を足す(判明前は出さない)。`Push` クライアント側に薄い問い合わせメソッドを足してよいが、**購読状態を変える処理は呼ばない**。`ConfirmDialog` に条件付き補足を渡す口が無ければ `Dialog` で組む
- 現行のサインアウト処理(`MenuScreen` の `onLogout`。`817409b` 時点で `App.tsx:1721-1725` 付近)は `pushApi.disableThisDevice()` → `client.switchSession(null)` の順。**順序は変えない**が、確認を挟むことで押し間違いによる購読消失を防ぐ(J6-2)
- 完了メッセージは現行どおり `authMessage` に「サインアウトしました」を入れる(`Toast` 化は 2/5)。**語は「ログアウトしました」から「サインアウトしました」に変える**(U-2)

### 3.5 `App.tsx` の配線

- `beginLogin` から `window.confirm` のブロックを削除する(**廃止D-3**)。`beginLogin` は「接続確認 → `auth.begin`」だけを担い、**確認は呼び出し側(DLG-1 / DLG-2)が済ませてある**前提にする
- `AccountScreen` のルーティングと、メニューからの遷移(アカウント行の `onOpen`)を足す
- `MenuScreen` へ渡していた `onLogin` / `onLogout` は `AccountScreen` 側へ移す
- 部屋の画面はメニューより先に return されるので、**対局中にアカウント行が出ないことは構造的に満たされる**(A-7)。既存の return 順序を変えないこと

- 「Googleでつなぐ」を押すと DLG-1 を経て Google へ飛ぶ。**失敗時は依然ブラウザに生 JSON が出る**(J4-1 は 2/5 で解消)
