# みんなでつくろう 大富豪 プロダクトバックログ

企画書(`docs/企画書.md`)の確定内容を Epic とユーザーストーリーに分解したもの。開発者はこのファイルだけで「次に何を作るか」を判断し、進捗に応じて更新する。

## 1. 目的と運用ルール

### 状態値

各ストーリーは次のいずれかの状態を持つ。**状態の記載がないストーリーは「未着手」**とみなす(2026-07-29 に全ストーリーの状態を実態へ同期済み。作業記録の正は `docs/impl-progress.md`)。

| 状態 | 意味 |
|---|---|
| 未着手 | まだ手を付けていない(デフォルト。記載省略可) |
| 進行中 | 実装・作業中 |
| 保留 | 未確定事項の決定待ちなど、着手できない理由がある(理由を併記する) |
| 完了 | 受け入れ条件をすべて満たした |
| 破棄 | やらないと決めた(理由を併記して残す。削除しない) |

状態を変えるときは、ストーリーの末尾に `状態: 進行中` のように追記する。

### 並び順の意味

- **着手順は「フェーズ昇順 → 本文書の記載順」で読む。** 同一フェーズ内では、上にあるストーリーほど先に着手する。
- ただし**「依存」に挙げたストーリーが未完了の間は着手できない**(依存が記載順に優先する)。例: AI-02 は文書上 CX-03 より前にあるが、CX-03 完了後にしか着手できない。
- Epic 単位でまとめて記載しているため、Epic 内にフェーズの異なるストーリーが混ざることがある(例: E2 の AI-02 はフェーズ 2)。その場合も**フェーズが記載順に優先する**。
- 同一フェーズ内の順序の意図は「4. 並び順の設計意図」にまとめた。依存関係を満たす範囲で、並行着手してよいものもそこに明記している。

### 追加・分割のガイドライン

- 1 ストーリー = 1 つの価値単位。「大富豪が遊べる」のような大きな単位は分割する。
- 受け入れ条件は 2〜4 個の検証可能な箇条書きにする(「〜できる」「〜が記録される」など、確認方法が想像できる文にする)。
- 新規ストーリーは該当 Epic の中の、優先順として正しい位置に挿入する(末尾に積まない)。
- ID は Epic 接頭辞 + 連番。欠番が出ても再利用しない。
- 企画書にない機能を追加する場合は、まず企画書側を更新してからバックログに載せる。

  - 受け入れ条件:
    - ゲーム開始時に配札され、自分の手札だけが自分に見える
    - GE-01 のルール上出せるカードだけが出せる(不正な手は拒否される)

### E2: 対戦 AI(非 LLM ロジック)

- **[AI-01]** プレイヤーとして、AI プレイヤーを相手にすぐ 1 人で対戦を始めたい。それは相手を集めなくても大富豪を楽しめるようにするためだ。
  - 受け入れ条件:
    - AI 対戦を選ぶと、人間 1 人 + AI プレイヤーでゲームが開始する
    - AI は合法手のみを選び、ゲームが最後まで止まらず進行する
    - 対局処理で LLM などの外部 AI API を一切呼ばない(ルールベースロジックのみ)
  - フェーズ: 1 / 依存: GE-03
  - 状態: 完了

- **[AI-02]** 開発者(運営)として、提案ルールが追加されたときに対戦 AI がどう追従するかの方針を決め、パイプラインに組み込みたい。それは新ルール下でも AI 対戦が破綻しないためだ。
  - 受け入れ条件:
    - 追従方針(ルール追加時に codex が AI ロジックも更新する/AI は未知ルールを無視して合法手のみ打つ、など)が決定され文書化されている
    - 新ルールが有効な卓で AI が不正手や進行停止を起こさないことをテストで確認できる
    - 方針が E7 の自動実装フローに組み込まれている
  - フェーズ: 2 / 依存: AI-01, CX-03 / 関連未確定事項: §9-3
  - 状態: 完了

### E3: マルチプレイ・ルーム

- **[MP-01]** プレイヤーとして、部屋を作って他の人を招き、人間同士で対戦したい。それは仲間内で遊ぶのが大富豪の原点だからだ。
  - 受け入れ条件:
    - 部屋を作成でき、作成後は待機画面で参加者が集まるのを待てる(対戦人数は 4 人固定 §3.2)
    - 他のプレイヤーがその部屋に参加でき、待機画面の「開始」でゲームが始まる
    - 全参加者に同じ進行がリアルタイムで同期される
    - 対局中の離脱でゲームが破綻しない(離脱時の扱いは着手時に決定し文書化する)
  - フェーズ: 1 / 依存: GE-03 / 関連未確定事項: §9-7(マッチング方式)
  - 状態: 完了
