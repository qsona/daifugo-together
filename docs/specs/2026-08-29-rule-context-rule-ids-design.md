# RuleContext rule IDs design

## 背景

「大富豪の余裕」は、同じゲームで「号砲」が有効なら発動しない。前戦1位は
`ctx.setHistory` から読めるが、現行のルール契約にはセット開始時に固定された
ルール構成を読む手段がない。ルール専用KVは他ルールから読めず、共有状態の代用に
使ってはならない。

## 決定

`GameView` に `readonly ruleIds: readonly RuleId[]` を追加する。値は
`GameConfig.ruleChain` の `ruleId` を、固定済みの優先順位順のまま写した配列とする。
通常実行では他のゲームビューと同様に複製・deep freezeし、trusted simulationでも
ゲーム設定から決定的に生成する。

ルールは「特定ルールが同じゲームで有効なら発動しない」のような構成依存条件に
この配列を使う。ルールの内部状態や別ルールのKV、実行結果は公開しない。

## 互換性

既存ルールは `ruleIds` を読まないため挙動は変わらない。リプレイとAI simulationは
いずれも固定済み `GameConfig.ruleChain` から同じ配列を再構成でき、永続形式の変更は
不要である。

## 検証

- 複数ルールを含む設定で、フックが優先順位順のID一覧を受け取る。
- 通常実行で配列が凍結され、ルールから変更できない。
- CX-01プロンプトが新しい読み取り語彙を説明し、版を繰り上げる。
- 全既存ルール、リプレイ、AI simulationの回帰検証を `pnpm verify` で行う。
