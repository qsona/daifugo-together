# 部屋作成前のなまえ確認とログイン導線

- 日付: 2026-08-23 / 状態: 完了
- 関連: [E03: マルチプレイ](../epics/E03-multiplayer.md) / [E15: 引き継ぎ登録・ログイン](../epics/E15-auth-account.md) / [UIライティングガイド](../design/ui-writing-style-guide.md)

## 1. 背景と目的 [変更不可]

匿名ユーザーが友だちの部屋へ入るときは、招待コードと一緒になまえを確認・変更できる。一方、部屋を立てるときは確認なしで作成されるため、自動生成されたゲスト名のままホストになることに気づきにくい。

部屋を立てる側にも、部屋作成前になまえを確認・変更する自然な動線を加える。また、未ログインの利用者がその場で Google ログインを選べるようにする。

## 2. ユーザー体験 [変更不可]

- 匿名ユーザーが「部屋を立てる」を選ぶと、部屋を作る前に「なまえ」入力画面へ進む。
- 画面には現在のなまえを入力済みで表示し、「Googleでログイン」ボタンと「部屋を立てる」ボタンを置く。
- 「このなまえが、部屋のみんなに表示されます」などの補助文言は置かない。
- Google ログインの目的を説明する文言も置かない。ログインを知っている人が見つけられるボタンだけを置く。
- なまえを変更して部屋を立てると、変更を保存してから部屋を作る。
- Google ログインを選び、ログイン完了またはキャンセルでアプリへ戻ったときは、部屋作成のなまえ確認画面へ戻る。自動では部屋を作らない。
- ログイン済みユーザーは追加の確認画面を挟まず、従来どおり部屋を作る。
- ひとり練習の導線は変更しない。

## 3. 受け入れ条件 [変更不可]

- [x] 匿名ユーザーが「部屋を立てる」を押すと、部屋作成前になまえ入力と「Googleでログイン」「部屋を立てる」が表示される
- [x] なまえ入力には現在の表示名が入り、既存と同じ 1〜10 コードポイントの検証が働く
- [x] 変更したなまえの保存が成功してから community 部屋を作る
- [x] なまえの保存に失敗した場合は部屋を作らず、同じ画面で再試行できる
- [x] Google ログインの確認を閉じると、入力途中のなまえ確認画面へ戻る
- [x] OAuth 完了・キャンセル・再試行可能な失敗の後も、部屋作成のなまえ確認画面へ戻れる
- [x] OAuth から戻っただけでは部屋を自動作成しない
- [x] ログイン済みユーザーと、ひとり練習の作成動線は従来どおり
- [x] 友だちの部屋へ入る匿名ユーザーにも、既存のなまえ入力と同じ場所から「Googleでログイン」を選べる

## 4. スコープ外 [変更不可]

- Google ログインの必須化
- 過去にログインした利用者を端末履歴から判別する仕組み
- 対局中・待機室でのログイン導線
- サーバー、認証 API、部屋プロトコルの変更

## 5. 詳細仕様 [変更可・記録必須]

- `PlaySheet` に匿名ユーザー向けの `create` ステップを追加する。
- `user:rename` が必要な場合は `room:create` より先に実行する。
- OAuth 前に復帰先を `sessionStorage` へ保存し、コールバック処理で一度だけ復元する。
- 復帰先は `create` または `join` とし、`join` は入力済み招待コードも保持する。
- 保存領域が利用できない環境では復帰情報を保存できなくても、認証自体は妨げない。
- ログインボタンには既存の `GOOGLE_LOGIN_LABEL` を使う。説明文は表示しない。

## 6. 技術設計メモ [参考]

- `PlaySheet.onCreate` に任意の `displayName` を渡し、`App` 側で既存の join と同じ rename-before-action を行う。
- `PlaySheet.onLogin` から `create` / `join` の復帰情報を `App` へ渡す。
- 既存の `ConnectDialog` と OAuth 完了処理を再利用する。
