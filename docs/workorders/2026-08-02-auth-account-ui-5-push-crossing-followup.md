## 4. 着手前に必要なもの

1. **裁定 Q-9**: 未登録者に通知設定画面そのものを見せるか。
   - (a) 画面は見せて購読ボタンだけを「Googleでつなぐ」に差し替える(**現在の実装はこちら**)。「何が手に入るのか」を先に見せられるが、原則 4(まだ起きていない制限の予告)に触れうる
   - (b) メニュー(おしらせ)から通知設定へ入れるのは登録済みだけにする。単純だが、通知の存在自体を知る機会が消える
   - **J9-4 の状態表示の設計がこの裁定に依存する**(未登録に「この端末: オフ」を見せるかどうかが変わる)
2. **通知設定画面の画面仕様**(状態表示・許可拒否からの回復手順・射程の見出し)。`push/install.ts` の `detectInstallEnvironment` が既に環境を判定しているので、回復手順は A2HS 案内と同じく環境で分岐させられる
3. **テストの網羅軸**(レビュー §0.8 の P2 引き継ぎ): 匿名 / 登録済み / VAPID 未設定 / OS 許可拒否 / iOS タブ / ホーム画面アプリ

## 5. 注意

- **J9-3 は J4-4(認証の失敗が 3 原因で 1 文言)と同じ形の欠落だが、対象コードも画面も別**(`push/client.ts:175-184`)。2/5 の作業に混ぜない
- Push は「登録ゼロで遊べる」(E15 §1.1)と衝突する最初の機能である。サーバーは購読・種別設定のすべてに登録済みを要求し、匿名は 403 `registration_required`(`packages/server/src/push/service.ts`)。これは E17 の設計判断であり、**本フェーズ群では動かさない**
