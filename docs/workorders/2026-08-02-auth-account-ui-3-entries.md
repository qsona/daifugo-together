> 全体像・裁定待ちの前提表・共通ルールは [0/5 概要](2026-08-02-auth-account-ui-0-overview.md) を先に読むこと。

## 1. 目的

**開発者の Critical (3)「重要なところでログイン動線がない」を解消する。**

- **N-8(優先度 高)**: A2HS 案内が「もう一度Googleでログインしてください」と**文で指示するのに、その画面に導線がない**(`InstallGuide.tsx:119-121`)。ここから DLG-1 を直接開けるようにする。**iOS では通知機能に到達するための必須要件**(レビュー §0.8)
- **F-1 / F-2(Q-1 = B・廃止D-5)**: リザルトからの直接 OAuth 遷移を廃止し(J3-1)、**退室直後のメニュー**で 1 枚だけ誘う
- **G-1 / G-2(U-4・廃止D-4)**: 提案画面の Callout を 1 枚にし、枠うまりのパネルから DLG-1 へ
- **U-2**: 認証語彙を「Googleでつなぐ」に統一する

## 3. やること

### 3.1 N-8: A2HS 案内から認証を始められるようにする

`packages/web/src/components/InstallGuide.tsx`。

- 現行の注記(iOS 分岐の末尾)「ホーム画面のアプリはブラウザとは別のアプリとして開きます。追加したあとは、もう一度Googleでログインしてください。」を、**語彙を統一したうえで導線つきにする**
- **登録状態で文を分岐する**(ワイヤー §4 の A2HS 節)

| 状態 | 文 | 導線 |
|---|---|---|
| 登録済み | ホーム画面のアプリはブラウザとは別のアプリとして開きます。追加したあとは、もう一度Googleでつないでください。 | 「Googleでつなぐ」→ **DLG-1** |
| 未登録 | 追加すると、いまの記録は引きつげません。先にGoogleでつないでください。 | 「Googleでつなぐ」→ **DLG-1** |

- `InstallGuide` は現在 `environment` しか受け取らない純粋な部品なので、**導線は任意の props(`onConnect?: () => void` と `registered?: boolean`)で受け取る**。渡されないときは現行どおり文だけを出す(`PushOfferDialog` など渡し漏れがある呼び出し側で壊れないようにする)
- 表示元は `PushSettingsScreen` と `PushOfferDialog` の 2 つ。**どちらも部屋の外**なので E15 §2.3(対局中は導線を出さない)と衝突しない
- `PushOfferDialog` の中から DLG-1 を開く場合、**ダイアログが二重にならないよう先に自身を閉じる**こと。開く前に「この端末で通知を受け取りたい」という意図を保持する既存の仕組み(`markOfferAfterLogin` / `consumeOfferAfterLogin`)を壊さない

### 3.2 F-1: リザルトの登録導線を廃止する(廃止D-5・Q-1 = B)

- `packages/web/src/screens/SetResultScreen.tsx` の `onRegister` と「記録を残す」ボタン(`:133-138`)を削除する
- `App.tsx` の `showResultAuthPrompt` と `{...(showResultAuthPrompt ? { onRegister: beginLogin } : {})}` を削除する
- **`AUTH_RESULT_PROMPT_KEY`(端末で生涯 1 回のフラグ)は廃止**し、F-2 の頻度管理に置き換える(下記)

### 3.3 F-2: 退室直後のメニューで 1 枚だけ誘う(Q-2)

メニュー最下部に `Callout`(`action` つき)を 1 枚。**主要導線の上流に置かない。**

```
本文  : 今日の記録は、この端末だけに残っています。Googleでつなぐと、ほかの端末でも続きをあそべます。
ボタン: Googleでつなぐ  → DLG-1(アカウント画面を経由させない)
```

表示条件:

```
未登録 && セットを最後まで遊んで退室した && 前回表示から 3 セット以上(初回は無条件)
```

- **途中でやめた退室では出さない**(2b820ca の「対局をやめますか?」経由。`docs/design/quit-game-flow.md`)。遊びを中断した直後に登録を勧めるのは筋が悪い
- **表示済みフラグは実際に描画された時点で立てる**(現行は表示の直前に書くのでリザルトを一瞬で抜けても消費される。J3-4)
- 保存先は既存の `storage`(`browser-storage.ts` 経由)。キーは新設し、`AUTH_RESULT_PROMPT_KEY` の旧値は読まない
- **メニューには他に `Callout` が無い**ことを確認する(1 画面 1 枚)
- ダイアログにはしない(遊び終えた直後に操作を塞ぐと次に遊ぶ人の邪魔になる)

### 3.4 G-1 / G-2: 提案画面(U-4・廃止D-4・J7-1〜J7-4)

`packages/web/src/screens/ProposalFormScreen.tsx`。

1. **常設 Callout を削除**(廃止D-4): `ANONYMOUS_SLOT_HINT`(`:48-49`「登録しなくても、1つずつ提案できます。Googleで登録すると、いくつでも提案できます。」)と、それを常設している箇所を消す。定数も削除する
2. **AI 確認の Callout を残す 1 枚にし、2 文にする**。都道府県の断り書きは**都道府県欄(`817409b` 時点で `:327` 付近。`SelectField` ではなく自前のラベル + セレクトになっているので、既存の構造に合わせた置き場を選ぶ)の直下** へ畳む
   ```
   Callout: 提案はAIが確認します。わるい命令を混ぜるとイエローカードになります。
   都道府県欄の caption: あそんでいた記録として残ります
   ```
   - 「わるい命令」は**ガイド §5.2 の言い換え表に無い**提案語(現行は「不正な命令」)。**採るなら言い換え表への追記が要る**(ガイド §11.2)。開発者に確認し、却下されたら現行の「不正な命令」のままにする
3. **枠うまりパネル(G-2)**: 進行中の提案行そのものをマイ提案への導線にする(J7-4)。`REGISTERED_SLOT_HINT` の「Googleで登録すると」を **「Googleでつなぐと」**に差し替え、ボタンのラベル「Googleでログイン」(`817409b` 時点で `:278`)を **「Googleでつなぐ」**にする。押した先は **DLG-1**(アカウント画面を経由させない)
4. 通知の Callout(未登録者に出る「Googleで引き継ぐ」)も**「Googleでつなぐ」**に揃える(下記 U-2)
5. 状態タグは `STATUS_LABELS`(`status-labels.ts`)のまま。他画面で別名を作らない

### 3.5 U-2: 語彙の統一

**画面に出る認証語彙を「Googleでつなぐ」1 語に揃える。**現在の置き場は 9 か所(レビュー §0.5 の 7 か所 + `817409b` で増えた 2 か所。0/5 §4)。

| 場所 | 現在 | 変更後 |
|---|---|---|
| `InstallGuide.tsx`(A2HS 注記) | もう一度Googleでログインしてください | §3.1 の文に差し替え |
| `ProposalFormScreen.tsx`(枠うまりパネルのボタン) | Googleでログイン | **Googleでつなぐ** |
| `ProposalFormScreen.tsx`(`REGISTERED_SLOT_HINT`) | Googleで登録すると | **Googleでつなぐと** |
| `ProposalFormScreen.tsx`(`ANONYMOUS_SLOT_HINT`) | — | **削除**(§3.4) |
| `ProposalFormScreen.tsx`(通知の Callout) | Googleで引き継ぐ / Googleで引き継ぐと | **Googleでつなぐ** / **Googleでつなぐと** |
| `PushSettingsScreen.tsx`(未登録の Callout・ボタン) | Googleで引き継ぐ / Googleで引き継いでください | **Googleでつなぐ** / **Googleでつないでください** |
| `SetResultScreen.tsx` | 記録を残す | **削除**(§3.2) |
| `MenuScreen.tsx` の旧ボタン | 引き継ぎ・ログイン ほか | 1/5 で削除済み |
| `App.tsx` の完了・サインアウトの文 | — | 1/5・2/5 で対応済み |
| `InviteCode.tsx:52` | このリンクを送ると、ログインしていない友だちも参加できます | **このリンクを送ると、Googleでつないでいない友だちも参加できます**(下記の注) |

- **`InviteCode` の 1 文は判断が割れうる。**ここが言いたいのは「アカウントを持っていない人でも入れる」であって、認証操作の名前ではない。「Googleでつないでいない」は長く、招待の文脈では説明過多になる。**代案: 「このリンクを送れば、だれでも参加できます」**(認証語彙を使わずに済ませる)。**どちらを採るかは開発者に確認する**。確認が取れないうちは現行のままにしてよい(語彙統一の主目的は認証操作のラベルであり、この 1 文は周辺)
- **格助詞は「で」に固定**(ワイヤー §2)。「Googleと」は使わない
- **`PushSettingsScreen` はこの語彙の差し替え以外を触らない**(表示条件・状態表示・エラー分類は 5/5)
