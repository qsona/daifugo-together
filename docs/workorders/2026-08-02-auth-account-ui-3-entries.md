## 3. やること

### 3.1 N-8: A2HS 案内(**`817409b` で縮小。作業は語彙の差し替えのみ**)

**前提の変化(コントローラー裁定 2026-08-02 — 現実装を前提として採用する)**

ワイヤー §4 の A2HS 節とレビュー §0.7 N-8 は、「未登録の人が A2HS 案内を読み、そこから認証を始められない」ことを Critical (3) の実例として扱っていた。**しかし `817409b` で `InstallGuide` の表示元がすべて登録済み限定になり、未登録者はこの案内に到達しなくなった。**

| 表示元 | 条件 | 到達する人 |
|---|---|---|
| `PushSettingsScreen.tsx:83` | `registered && !environment.standalone` | 登録済みのみ |
| `PushOfferDialog`(`kind === 'install'`) | `offer()` の呼び出し口が 3 つとも登録済みガード済み | 登録済みのみ |

したがって:

- **未登録分岐(「追加すると、いまの記録は引きつげません。先にGoogleでつないでください。」)は到達不能なので作らない。**ワイヤー §4 の A2HS 節のこの行は実装しない
- **A2HS 後の再ログイン問題の受け皿は、この画面ではない。**ホーム画面アプリ側では `userToken` が引き継がれず未登録の新しいゲストとして立ち上がるが、その人が通知設定画面を開けば **`817409b` が実装した未登録向け Callout +「Googleで引き継ぐ」ボタン**(`PushSettingsScreen.tsx:67-82`)が出る。加えて **1/5 のアカウント行**が、どの画面から来ても「いま未登録である」ことと認証への入口を常時示す。**この 2 つが受け皿である**
- したがって案内の文が指す「もう一度つなぐ」の実行は**ホーム画面アプリ側**で起きる。**ブラウザ側のこの案内にボタンを足しても、押す人は既に登録済みで、押すと切替(`switched`)の意味になってしまう** — だから**ボタンは足さない**

**このフェーズでやること(`packages/web/src/components/InstallGuide.tsx`)**

- iOS 分岐の末尾の注記を、語彙だけ §2 に揃える。**登録状態による分岐も新しい props も追加しない**
  ```
  変更前: ホーム画面のアプリはブラウザとは別のアプリとして開きます。追加したあとは、もう一度Googleでログインしてください。
  変更後: ホーム画面のアプリはブラウザとは別のアプリとして開きます。追加したあとは、ホーム画面のアプリでもう一度Googleでつないでください。
  ```
  - 「ホーム画面のアプリで」を足したのは、**どこでつなぎ直すのかが現行文では読み取れない**ため(ブラウザ側でつなぎ直しても意味がない)。2 文・敬体・句点ありでガイド §3 に収まる

**`InstallGuide` / `PushOfferDialog` から DLG-1 へは配線しない(現行動作を維持する)。**理由は上記のとおり押す人がいないため。`PushOfferDialog` の構造(`markOfferAfterLogin` / `consumeOfferAfterLogin` による認証後の復帰)は**触らない**。

**実装メモ(不変条件・レビュー §0.9 J9-2 の追記)**: `push/client.ts` の `subscribeProposalResults` は `Notification.requestPermission()` を最初に呼ぶ構造のままである(user activation を失わないための意図的な順序)。安全なのは**呼び出し口 3 つがすべて登録済みを保証しているから**にすぎない。**登録済みガードのない新しい通知の入口を足すと J9-2 が即座に再発する。**本フェーズで通知まわりの入口を増やさないこと。

### 3.3 F-2: 退室直後のメニューで 1 枚だけ誘う(Q-2)

メニュー最下部に `Callout`(`action` つき)を 1 枚。**主要導線の上流に置かない。**

```
本文  : 今日の記録は、この端末だけに残っています。Googleでつなぐと、ほかの端末でも続きをあそべます。
ボタン: Googleでつなぐ  → DLG-1(アカウント画面を経由させない)
```

表示条件:

```
未登録 && セットを最後まで遊んで退室した && 前回表示から 3 セット以上(初回は無条件)
```

- **途中でやめた退室では出さない**(2b820ca の「対局をやめますか?」経由。`docs/design/quit-game-flow.md`)。遊びを中断した直後に登録を勧めるのは筋が悪い
- **表示済みフラグは実際に描画された時点で立てる**(現行は表示の直前に書くのでリザルトを一瞬で抜けても消費される。J3-4)
- 保存先は既存の `storage`(`browser-storage.ts` 経由)。キーは新設し、`AUTH_RESULT_PROMPT_KEY` の旧値は読まない
- **メニューには他に `Callout` が無い**ことを確認する(1 画面 1 枚)
- ダイアログにはしない(遊び終えた直後に操作を塞ぐと次に遊ぶ人の邪魔になる)

### 3.4 G-1 / G-2: 提案画面(U-4・廃止D-4・J7-1〜J7-4)

`packages/web/src/screens/ProposalFormScreen.tsx`。

1. **常設 Callout を削除**(廃止D-4): `ANONYMOUS_SLOT_HINT`(`:48-49`「登録しなくても、1つずつ提案できます。Googleで登録すると、いくつでも提案できます。」)と、それを常設している箇所を消す。定数も削除する
2. **AI 確認の Callout を残す 1 枚にし、2 文にする**。都道府県の断り書きは**都道府県欄(`817409b` 時点で `:327` 付近。`SelectField` ではなく自前のラベル + セレクトになっているので、既存の構造に合わせた置き場を選ぶ)の直下** へ畳む
   ```
   Callout: 提案はAIが確認します。わるい命令を混ぜるとイエローカードになります。
   都道府県欄の caption: あそんでいた記録として残ります
   ```
   - 「わるい命令」は**ガイド §5.2 の言い換え表に無い**提案語(現行は「不正な命令」)。**採るなら言い換え表への追記が要る**(ガイド §11.2)。開発者に確認し、却下されたら現行の「不正な命令」のままにする
3. **枠うまりパネル(G-2)**: 進行中の提案行そのものをマイ提案への導線にする(J7-4)。`REGISTERED_SLOT_HINT` の「Googleで登録すると」を **「Googleでつなぐと」**に差し替え、ボタンのラベル「Googleでログイン」(`817409b` 時点で `:278`)を **「Googleでつなぐ」**にする。押した先は **DLG-1**(アカウント画面を経由させない)
4. **送信成功後(`accepted`)の未登録状態でも Callout を 1 枚に保つ**。現状ここには通知の Callout(`817409b` 時点で `:407-420`。「提案の結果が出たら、この端末へお知らせできます。Googleで引き継ぐと、通知を受け取れます。」+ ボタン「Googleで引き継ぐ」)が出るが、**AI 確認の Callout と同時に出ると 2 枚になる**(J7-1 と同じ違反)。次のどちらかで解く
   - **推奨**: `accepted` の分岐では **AI 確認の Callout を出さない**(提案は送り終わっており、「提案はAIが確認します」は次の送信のための注記だから、この状態では不要)。通知の Callout だけを残す
   - あるいは 2 つを 1 枚に統合する
   - どちらを採っても**通知の Callout の文言は「Googleでつなぐ」に差し替える**(下記 U-2)。通知の提示自体(`pushRegistration.begin` = `beginPushLogin`)の挙動は変えない — `markOfferAfterLogin` による認証後の復帰を壊さないこと
5. 状態タグは `STATUS_LABELS`(`status-labels.ts`)のまま。他画面で別名を作らない
