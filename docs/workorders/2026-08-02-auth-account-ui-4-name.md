## 3. やること

### 3.1 なまえ入力画面 C-1

`packages/web/src/screens/NameScreen.tsx`(名前は任意。ASCII で命名すること)。ルーティングに追加する。

```
AppBar: なまえ (戻る → アカウント画面)
ラベル: なまえ            カウンタ: 3 / 10
入力  : 現在のなまえをプリセット
primary: これにする
```

- **入口も戻り先もアカウント画面だけ**(保存しても中断しても戻る)。他画面から来られるようにしない
- **現在値をプリセットして開く**(空で開かない)
- カウンタは提案フォームと同じ流儀: `countCodePoints` で `n / 10`、**入力時に `clampCodePoints` で切り詰める**(`ProposalFormScreen.tsx:51` の実装を共有可能な場所へ切り出して再利用する)。**コードポイント数え**である点が重要(`String.length` では絵文字で食い違う)
- 説明文(「10文字までで入力してください」)は**置かない**(カウンタと重複)
- 検証は `clientPayloadSchemas['user:rename'].safeParse` を**そのまま**使う(`PlaySheet.tsx:73-79` で確立済みの流儀)。**UI 側で条件を足さない・緩めない**(J8-4)
- 送信は `multiplayer/client.ts` の `rename`(= `user:rename`)
- **成功トーストは出さない。**アカウント行の表示が変わることが確認そのもの(原則 3)
- **接続未確立(`connection !== 'ready'`)**: 送る前に分かるので「これにする」を押せない状態にし、理由の 1 行を**ボタンの下流**に出す(「サーバーとつながるまで待ってください」)。入力自体は許可し、値は保持する

### 3.2 エラー C-2(`protocol.ts:206-219` の 3 条件に 1 対 1)

```
① trim 後 0 文字        : なまえを入れてください      (+ primary を無効化)
② 10 コードポイント到達 : 文言なし。カウンタが 10 / 10 で止まることだけが伝達手段
③ 制御文字             : 使えない文字が入っています
```

- ②は切り詰めるので**「11 文字以上」という状態自体が発生しない**
- 絵文字・全角は**通す**(サーバーが許しているものを UI で狭めない)
- ①③は色だけに頼らず**枠の太さでも異常を示す**(`InputField` の `error` を使えば既存スタイルが効く)
- **現行 `PlaySheet` は 3 条件を 1 文にまとめている**(「なまえは1〜10文字で、改行なしで入力してください」)。**本発注は①③を分ける方式を採る**(何を直せばよいかがその場で分かる)。§3.4 で `PlaySheet` もこちらへ揃える

### 3.3 保存中・保存失敗 C-3

```
保存中  : ボタンのラベルを「保存中…」+ disabled。入力欄は編集不可にするが値は消さない
保存失敗: 保存できませんでした。もう一度ためしてください。   (入力欄の下流にその場で出す)
```

- 失敗は **`BAD_PAYLOAD` / `INTERNAL` / `NOT_IN_ROOM` / `ROOM_CLOSED` の 4 種とも同じ 1 文**(ユーザーの取る行動が同じ)。**入力値は保持**してそのまま再送できるようにする
- 2 文目「もう一度ためしてください。」は `RETRY_GENERIC_ERROR` と共通なので**定数を共有する**(2/5 で切り出し済みならそれを使う)
- **トーストにもモーダルにもしない**(画面に入力欄がある = その場のフォームエラーが成立する唯一の場所)
- 永続化は部屋の外でも走る(`socket-gateway.ts:664` が `if (current)` ブロックの外)ので、**メニューからの改名は部屋の状態に関係なく成立する**

### 3.4 DLG-1 のインライン編集(Q-6 = B)と `PlaySheet` の統一(N-9・N-10)

**DLG-1(1/5 で作成済み)に「つなぐときのなまえ」の枠を足す。**

```
枠のラベル: つなぐときのなまえ
通常時    : なまえ + 小ボタン「変える」
編集中    : カウンタ + 入力欄 + [やめる][これにする]
```

- **独立画面(C-1)へ遷移しない。**遷移するとダイアログが閉じて認証フローが切れ、提案画面や誘いから来た人が一度も訪れていないアカウント画面に着地する
- **編集中はダイアログの「もどる」を出さない。**外側の「Googleへ進む」は無効化する。有効なのは編集の中の 2 ボタンだけ
- 入力欄・カウンタ・検証・エラー文言は **C-1 / C-2 と同一の実装を使い回す**(共通コンポーネントか共通フックに切り出す)
- 「これにする」は `user:rename` を送り、**ack を待ってからダイアログの表示名を差し替える**。改名に失敗したら C-3 と同じ 1 文をその場に出し、**認証フローは中断しない**(古いなまえのまま「Googleへ進む」に進める)
- **`PlaySheet` でなまえを設定ずみの人にも同じ枠を出す**(既定名でない人には確認だけになる)。経路によって DLG-1 の見た目が変わると、実行口が 1 つであるという規律が崩れる

**`PlaySheet` を揃える**(`screens/PlaySheet.tsx:112-125`)。

- カウンタ(`n / 10`)と `clampCodePoints` による切り詰めを足す(現状は超過を入力させてからエラーを出す)
- エラー文言を C-2 の①③方式に揃える
- ラベルが「あなたのなまえ」(PlaySheet)と「なまえ」(C-1)で割れている。**どちらかに統一する。**推奨は **`PlaySheet` 側を「なまえ」にする**(C-1 / DLG-1 と同じ語にする)。キャプション「友だちに見えるなまえ・10文字まで」は文字数がカウンタと重複するので **「友だちに見えるなまえ」**に短くする
- **`PlaySheet` の入力自体は残す**(「入る直前の近道」という位置づけ)。置き場はアカウント画面が唯一という原則は、**アカウント画面ができたことで既に満たされている**

### 3.5 Q-7 ステップ 1: 自席の呼び方を 1 か所に寄せる(**裁定に依存しない・表示は変わらない**)

現在 `'あなた'` のリテラルは **11 か所**に散っている。

```
App.tsx:445, 482, 518, 542, 600, 1402
game/table.ts:62, 123, 222
components/Table.tsx:105
screens/GameScreen.tsx:212
```

- **寄せ先は `packages/web/src/game/table.ts`**(view-model が既に切り出されている)
- **二重置換の対が 2 組ある**。どちらも view-model が `name` を「あなた」に置換したうえで `isSelf` も渡し、描画側が `isSelf` を見て**もう一度**置換している

| 組 | view-model 側 | 描画側 | 表示 |
|---|---|---|---|
| 1 | `game/table.ts:222` | `Table.tsx:105` | 対戦画面の席 |
| 2 | `game/table.ts:123` | `GameScreen.tsx:212` | あがり演出のトースト |

- **描画側の `isSelf` は強調のためだけに使い、名前の差し替えには使わない**形にすれば、二重置換は構造ごと消える
- `App.tsx` 側の 6 か所も、自席の表示名を決める共通関数(例: `seatDisplayName(name, isSelf)`)を経由させる
- **このステップで表示は 1 ピクセルも変わらない。**変わったら実装が間違っている

### 3.6 Q-7 ステップ 2: 待機画面の自席だけ「なまえ(あなた)」(**裁定後**)

- 待機画面のメンバー一覧(`App.tsx:445` の `waitingMembers`)の自席を **`ゆうた(あなた)`** の形にする。**対戦・リザルトの 10 か所は「あなた」のまま**
- 根拠: 待機画面は「これから遊ぶ相手に自分がどう見えているか」を確かめる唯一の場面で、他席に他人のなまえが並ぶ対称性から自分のなまえも見えていると分かる(説得の文ではなく事実の可視化)
- **ここでは改名させない**(対局中の改名は部屋の状態変化を伴う。`reducer.ts:962-985`)。動機はここで立ち、実行はアカウント画面で行う
- §3.5 が済んでいれば**変更は 1 関数の中だけ**で済む
