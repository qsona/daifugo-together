画面に載らないバックエンド処理と起点

  • 提案の自動実装パイプライン(§4.2・§5.1・§7): 起点は画面6「提案を送信する」。送信後にインジェクション検査 → 実装可否判断 → codex による自動実装 → デプロイ・反映、が順にバックエンドで走る。進行状況は画面7 のステータス(審査中 → 実装中 → リリース / 却下 / 実装失敗)として見え、リリースされたルールは全卓共通で有効になり(§4.5)、画面4・画面8 に現れる。検出時のみ画面9a/9b が表示される。
  • 評価集計と淘汰(§4.4・§4.3): 起点は画面5b「評価を送信」。セット(3 戦)ごとの「面白かったか」と、そのセットで発動したルールへの高評価・低評価を集計し、人気度・優先順位の更新(画面8 の表示に反映)と、低評価ルールの排除(画面8 の「排除済み」)が行われる。
  • 対戦 AI のロジック(§3.3)と開始時の自動補充(§3.2): 起点は画面2b「開始する」。開始時点の人間の人数を確認し、4 人に足りない分をサーバーが AI で自動補充する(枠指定 UI はない)。対局中の AI の手はサーバー側ロジックで決まる。画面上は AI バッジ(画面3・5a・5b)以外に UI を持たない。
