継続状態の表示 — 設計提案

作成日: 2026-07-31 / 対象: 対局画面(画面3)/ 位置づけ: 提案(未決定)。デザインシステム.md・UI文言・情報量ガイド.md・ingame-effects-design.md の上に載る
問題: 革命・イレブンバック・縛りは、発動の瞬間はカットインで分かるが、続いていることの表示が無い。 途中で目を離した人・あとから再接続した人・カットインをスキップした人は、いま 3 が強いのか 2 が強いのか、次に出せるスートが縛られているのかを知る手段が無い。 しかもこのゲームは提案ルールが増え続けるので、「革命アイコンを 1 個作って終わり」ではなく、状態を持つルール一般に効く仕組みが要る。

1. 考え方 — 状態は「それが死ぬ場所」に置く

スコープ例いつ消えるか置き場所消え方
局スコープ 革命 革命返し or 局の終わり 卓の枠(左上)に留まる小さなリボン = 局リボン 解除のカットインと同時に外れて飛んでいく
場スコープ イレブンバック・縛り 場が流れるまで 場の中心に置かれる札の形のチップ = 場チップ 場が流れるとき、札と一緒に中心へ吸い込まれる
場チップは「場の持ち物」なので、場が流れる吸い込みアニメーションがそのまま状態の終了通知になる。 「イレブンバックが終わりました」という文字はどこにも要らない — 札と一緒にチップが消えるのを 1 回見れば、 「これは場が流れると終わるやつだ」を仕組みごと学習できる(文言ガイド原則 3・5: 結果で伝える、行動で教える)。 逆に局リボンは場が何度流れても残り続ける。この「流れても残った」という絵が、革命とイレブンバックの寿命の違いを説明なしで教える。
原因と正味を分ける。革命とイレブンバックが重なると強さは元に戻る(反転×反転)。 マーカー(局リボン・場チップ)は「どのルールが生きているか = 原因」を示し、 いまどちら向きかの「正味」は §4 の強さ目盛りが一手に引き受ける。原因の数を数えて向きを暗算させない。

2. 新規部品

局リボン(卓の左上に留まる。タップでそのルールの詳細モーダル)
カットインの赤リボンが、引くときに小さくなって卓の左上に「刺さる」。発動(大きいリボンが走る)→ 継続(小さいリボンが留まる)→ 解除(外れて飛ぶ)が 同じ 1 枚のリボンの一生として読める。部品を増やしているようで、実はカットインの退場アニメーションに行き先を与えただけ。 文字はルール名だけ(「革命中」の「中」は書かない — 留まっていること自体が「中」)。斜め 2° はリボンの脇役傾き(トーン Do/Don't)。 面はカットインの red-500 ではなく red-600(caption サイズの cream-50 文字で AA 4.92。red-500 は大型表示限定)。 タップで既存のルール詳細モーダル(ingame-effects §2.2)。当たり判定は余白で 44px を確保。 複数の局スコープ状態が同時に生きたら縦に段重ね(カットインの段重ねと同じ文法)、3 枚目からは「+N」。
場チップ(場の中心。白面 = 札の造形。タップでそのルールの詳細モーダル)
白面・紺輪郭・ベタ落ち影 — 意図的に「札」と同じ造形にする。場チップは場に出ている札の仲間であり、札と同じ運命(場が流れたら消える)をたどるから。 局リボンの「ルール界の赤」との対比で、スコープの違いが色と形で読める。 縛りはスートの字が主役(♥♦ は red-500、♠♣ は navy-800 — 札のスート色と同じ規律)。ダブル縛りはスート構成をそのまま並べる。 登場は easing-pop で 1 回だけ弾む。以後は静止(常時ループ禁止)。 縛りはカットインを持たない静かなルールだが、チップが弾んで現れること自体が小さな発動告知になる(小さい出来事には小さい演出)。

A: 革命だけが生きている。局リボンが卓に刺さり、強さ目盛りが「つよい ← → よわい」に反転して現れる(§4)。手札の並びは変えない。
B: ♠Q(革命中なので Q より弱い J で上書き)→ ♠J でイレブンバックが発動し、スートが 2 連続で縛られた場面。 場の中心にイレブンバックと ♠しばりの場チップ、卓の枠に革命の局リボン。反転が 2 枚重なって正味は元の向きなので、強さ目盛りは出ない。 この場が流れると、場チップ 2 枚は札と一緒に吸い込まれて消え、局リボンだけが残る。

4. 強さ目盛り — 「正味の向き」の専任表示

通常(チュートリアルのみ表示・現行どおり)/ 反転中(全員に表示) よわい← →つよい つよい← →よわい
既存の StrengthScale(現在は未プレイ端末の basic solo 初戦のみ)を「正味の強さが反転している間はだれにでも出す」に拡張する。 手札は基本順(3 → 2)の固定ソートのままなので、反転中は「つよい」が左に来る — ラベルの位置が入れ替わること自体が信号。 「つよい」側だけ navy-800 の太字にして向きを一目にする(通常時も同じ規律)。 切り替わりの瞬間は 1 回だけ裏返るフリップ、prefers-reduced-motion では差し替えのみ。 革命 × イレブンバックで正味が元に戻ったら目盛りは消える — 原因(マーカー 2 枚)と正味(目盛りなし)が矛盾なく並ぶ。 手札を実効強で並び替える案は捨てた(§6)。

5. ライフサイクル — カットインに「行き先」を与える

革命
発動 — 現行どおり: 札が着地 → リボンが走る(300ms)→ 保持(750ms)
→
革命 イレブンバック
継続 — リボンは画面外へ引く代わりに縮みながら卓の左上へ刺さる(320ms)。場スコープなら中心に場チップが弾んで出る。スキップのタップでも同じ行き先へ直行
→
革命
終了 — 場チップは場が流れるとき札と一緒に吸い込まれる。局リボンは解除カットイン(革命返し)と同時に外れて飛ぶ。局が終われば全部消える
ingame-effects §1.1 のタイムライン(着地 → リボン → 場が流れる)はそのまま。変わるのはリボンの退場先だけ。
再接続・途中参加はスナップショットからマーカーを無演出で描く(カットインは再演しない)。あがりトーストの「初回描画時点の件数は基準として飲む」と同じ裁定。
発動チップ(c-achip)との整理: 状態を持つルールはマーカー自身が痕跡 + タップ導線を兼ねるので、そのルールの発動チップは出さない。発動チップは 8 切りのような一発もの専用に戻る。役割が重ならない。

6. データ供給と段階

現状クライアントは状態を一切受け取っていない。strengthNote.inverted はサーバー内で計算済みだが PlayerRoomView に載せていない(AI だけが使用)。イベント列からの推測は再接続で壊れる
追加する契約game.strengthInverted: boolean(正味)と game.statuses: { ruleId, name, scope: 'game' | 'field', suits? }[](原因。suits は縛りのスート構成)。スナップショット毎に状態から算出するので再接続に強い
フェーズ 1サーバー側で既知のコアルール 3 件だけをアダプタ実装(革命 = r0003 のメモリ / イレブンバック = r0005 のメモリ / 縛り = r0008 の bindingFromHistory 相当)。ルール契約(rule.ts の語彙)は変更しないので、5 箇所同時更新も rule-versions 繰り上げも不要
フェーズ 2提案ルールが状態を持ち始めたら、ルール契約に省略可能フック(例: presentStatus(context) → { active, label?, scope })を追加して自己申告制へ。このときは語彙拡張の全手順が要る。ラベルはルール名と同じ 12 文字制限

7. 検討して採らなかった案

手札を実効強で並び替える盤面で語る案としては最強だが、対局中に並びが変わると位置記憶が壊れて誤タップを生む。イレブンバックでは 1 つの場の間に 2 回並び替わる。固定ソート + 目盛り反転を採る
卓の緑を革命中だけ変色させる「世界がひっくり返る」演出としては魅力的だが、(1) 提案ルールの名前を伝えられず「ルール名は文字で堂々と」に反する、(2) 反転 2 枚重ねの正味を面の色で表せない、(3) 面全体の塗り替えは警報のトーンに寄る。将来の飾りとしては残しうるが背骨にはしない
AppBar に状態アイコン列操作対象(手札)から最も遠い上流に置くことになり、視線が届かない。AppBar はアウトゲームの領分でもある
「革命中」等の文字バナー常設状態語(〜中)の常設テキストは実況ログ廃止の決定に逆行する。ルール名だけを、位置と造形(留まるリボン / 場の札チップ)に語らせる
アクセシビリティ: マーカーはすべてボタン(タップでルール詳細モーダル)。aria-label は「革命 — 継続中。タップで説明」の形。 状態の増減の読み上げは未実装(対局画面に既存のライブリージョンが無いため見送り。将来 polite なライブリージョンを設ける際に 1 行だけ読み上げる)。色だけに頼らない(リボン=位置+形+文字、場チップ=文字、目盛り=文字位置)。 点滅・常時ループなし。prefers-reduced-motion ではドッキングとフリップをフェードに落とす。 新規トークンの追加はゼロ(既存トークンのみで構成)。
