# 対局を途中でやめる導線

作成日: 2026-08-01 / 対象: 対局中・戦間・待機中の退室 / 関連: [E03 §2.4](../epics/E03-multiplayer.md)、[ui-writing-style-guide.md](./ui-writing-style-guide.md)

## 1. 背景

対局中の画面には、部屋を離れる導線が 1 つも無かった。離脱そのものはサーバー側に実装済み(`room:leave` は `playing` 中も受け付ける)で、クライアントからは待機画面とセット結果画面からしか呼べていなかった。

## 2. 決めたこと

### 2.1 サーバーは変えない

`room:leave` を `playing` 中に送ると、席は消えずに `departed: true` + `controller: 'ai'` へ恒久切替され、AI が残りを打ち切る(E03 §2.4 の「AI 代行 vs 没収」の裁定どおり)。人間が 0 人になった部屋は `closed` になるので、ひとり練習(basic)は自分が抜けた時点で部屋ごと終わる。プロトコル追加もサーバー変更も不要で、足りないのは入口だけだった。

セット全体を中断する `requestDrain`(サーバー停止時のドレイン用)は今回使わない。「自分が抜ける」と「卓ごと畳む」は別の機能で、後者は他の人間プレイヤーの同意が要る。

### 2.2 入口はアプリバー左の「やめる」

`AppBar` の既存の `onBack`(←)は使わず、`leading` プロップでテキストボタンを置く。← は「前の画面に戻れる」という約束に読めるが、対局中は戻り先が無く、押すと不可逆だから。

置く画面は `GameScreen`(対局中)と `GameResultScreen`(戦間リザルト)。セット最終戦の結果表示には置かない(直後のセット結果画面に「ホームへ」がある)。

### 2.3 確認は 1 回、モードで中身を変える

| | ひとりで練習(basic) | みんなのルール(community) |
|---|---|---|
| 見出し | 対局をやめますか? | 対局をやめますか? |
| 本文 | なし | あなたの席はAIが引きつぎます。この対局にはもどれません。 |
| ボタン | やめる / もどる(primary) | 同左 |

basic に本文を置かないのは、部屋が閉じること以外に伝えるべき結果が無いため(情報量ガイド 原則 4)。community は AI 代行と「同じセット中は戻れない」が画面から読み取れないので書く。

primary は取り消し側(もどる)に付け、破壊的な選択を目立たせない。

待機画面の `window.confirm('部屋から出ますか?')` も同じ `ConfirmDialog` に置き換えた。ネイティブ confirm はボタン語彙を制御できず、ライティングガイド §3 の確認ダイアログ規則(選択ボタンは動詞の言い切り)を満たせない。

### 2.4 やめずに戻った場合

ダイアログを閉じるだけで、サーバーへは何も送らない。× ・スクリム・Esc でも同じ。

**ダイアログ表示中もゲームは止まらない**(手番タイマーも AI の手も進む)。サーバーが権威で他 3 人が待っている以上、クライアント都合で止められないため。時間切れになれば既存どおり AI が代打ちする。ひとり練習でも挙動を分けない — 分けると「練習では止まる」という誤った期待を作る。意図的なトレードオフとして受容し、緩和策はダイアログを即閉じられる導線を全部残すことに留める。

### 2.5 失敗したときは閉じない

`leaveRoom()` が失敗したらダイアログを開いたまま `RETRY_GENERIC_ERROR` を出す。閉じてしまうと、押したのに何も起きない状態になる。

### 2.6 ブラウザバック

部屋にいるあいだ、URL は `roomPath(room)` へ `replace` で同期され続ける。ブラウザバックしても描画はサーバースナップショット(`room`)が決めるので画面は変わらず、URL も即座に部屋のパスへ戻る。席だけサーバーに残る中途半端な状態にはならないため、今回は popstate に手を入れない。
