# インゲーム演出改善設計 — カットインの順序・ルールモーダル・自分の手番

作成日: 2026-07-30 / 対象: 対局画面(画面 3)と待機画面(画面 2) / 位置づけ: [E04 デザイン](../epics/E04-design.md)・[デザインシステム.md](./デザインシステム.md)・[UI文言・情報量ガイド.md](./UI文言・情報量ガイド.md) の実装後改訂

本書は、実データを画面に接続したあとの遊びテストで見つかった 3 件のインゲーム体験の問題と、その修正設計を定める。3 件は独立しているが、いずれも「対局中の一瞬に何が起きたかが読み取れない」という同じ症状の別の面である。

---

## 0. 背景と決定事項

### 観察された問題(2026-07-30 開発者)

| # | 症状 | 現状の実装 |
|---|---|---|
| 1 | ルール発動のカットインは良いが、**場が流れながらカットインするので何が出たか分からない** | 卓の札は `game.history` の再生。サーバーが `played` / `ruleFired` / `fieldCleared` を 1 スナップショットで送るため、リボンと同フレームで山が消える |
| 2 | 発動後に「8切り」などの**ルール名をタップすると画面遷移する** | `ActivationChip` も AppBar の「有効ルール N」も `/rooms/:id/rules` へ遷移し、`GameScreen` を丸ごとアンマウントする。手番は進み続けるのに盤面が見えない |
| 3 | **自分の手番が分かりにくい** | 手札トレイは手番で見た目が変わらない。残り時間バーは誰の手番でも出ており、「自分の番」の信号として働いていない |

### 決定事項(2026-07-30 開発者)

| 論点 | 決定 |
|---|---|
| カットインと場が流れる順序 | **出した札に一拍 → カットイン → 場が流れる**。3 段を順に見せる |
| ルール名タップの行き先 | **そのルール 1 件の詳細モーダル**。説明文つき |
| 説明文の取得元 | **by-id の図鑑 API を新設**(`GET /api/rules/{ruleId}`)。`PlayerRoomView` の契約は変更しない |
| AppBar の「有効ルール N」 | **モーダル化する** |
| 待機画面の「有効ルール N」 | **同じくモーダル化する**。部屋の中から開く有効ルール一覧は待機中・対局中で一律モーダル |
| ルール図鑑(フィルタ付きの一覧) | **画面遷移のまま**。中身が大きく、部屋の外からも開く |
| 自分の手番の見せ方 | **案 C: 相手の番はトレイを沈める + 自分の番はトレイを点灯 + 残り時間バーをトレイへ移す** |

## 1. カットインと場が流れる順序

### 1.1 タイムライン

8 切り 1 件が発動した場合。

| 時刻 | 起きること |
|---|---|
| 0ms | 出した札が卓に着地する。リボンはまだ出ない |
| 300ms | リボンが走り込む(`LEAD_IN_MS`) |
| 1050ms | リボンが引く(`HOLD_MS` 750ms。同時発動は `STAGGER_MS` 180ms ずつ段重ね) |
| 1050→1370ms | 卓の山が中心へ吸い込まれて消える(`--duration-slow` 320ms) |
| 1370ms | 空の場が確定する |

同時発動が n 件のとき、カットイン全体は `LEAD_IN_MS + HOLD_MS + STAGGER_MS × (n − 1)`。表示上限は現行どおり 3 件 + 「ほか」行なので、最長でも 1410ms + 流れる 320ms に収まる。

### 1.2 場を保持するしくみ

`tableSeats(room)` に「**最後の `played` より後ろの `fieldCleared` を無視する**」モードを足す。カットイン再生中はこのモードで卓を描くので、サーバーが場を流し済みでも札が卓に残る。

- カットインが終わったら卓に `isFlushing` を立てて 320ms 待ち、その後モードを解除して本物の(空の)状態へ合流する。`isFlushing` の吸い込みアニメーションは `Table.module.css` に実装済みで、現状は接続されていないだけである。
- 場を流さないルールでは、無視すべき `fieldCleared` が存在しないため、同じコードパスが何もしない。全員パスによる `fieldCleared` はカットインを伴わないので保持されない。

### 1.3 保持する対象を場の札だけに限る理由

手番ハイライト・残り枚数・「あなたの番」の点灯は**保持しない**。カットインは最長 1.4 秒あり、その間ずっと手番の合図を止めると §3 の修正が台無しになる。止めるのは「何が出たか」を伝えるために必要な場の札だけとする。

### 1.4 割り切り

保持中(最大約 1.4 秒)に次のプレイが着弾した場合、吸い込みアニメーションを飛ばして次の札の表示へ切り替わる。AI の思考待ちの方が長いため実害は薄いと判断する。カットインのスキップ(レイヤーのタップ)は一拍のあいだも有効で、押せば直ちに流れる段へ進む。

## 2. ルールのモーダル

### 2.1 by-id の図鑑 API

`GET /api/rules/{ruleId}`

- `RuleCatalogService.detail(ruleId)` を新設し、既存の `RuleCatalogRepository.get(ruleId)` と `#priorityRank` で、一覧 (`/api/rules`) の items と**同じ item 形**を 1 件返す。
- 存在しなければ 404 (`{ error: 'rule_not_found' }`)。
- 既存の `/api/rules` と同じ固定窓レート制限(120 回 / 分 / IP)に相乗りする。
- 優先度・人気度は一覧と同じくフィーチャーフラグでゼロ落ちする(`priority` / `popularity` が無効なら `null`)。
- ステータスによる出し分けはサーバーではしない。**実在すれば `status` をそのまま載せて返す**。「排除済み」の表示可否は今までどおりクライアントの `FEATURES.elimination` が決める。対局中に使っているルールは、その対局中に排除されても説明できるべきである。

クライアントは `RuleCatalogApi` に `get(ruleId)` を足す。

### 2.2 ルール詳細モーダル

発動チップのタップ、および有効ルール一覧モーダルの行タップで開く。

- 内容: ルール名 / 区分バッジ / 説明文 / 効果文(`ruleFired.message`。あれば)
- 名前は部屋のスナップショットに既にあるので**開いた瞬間に出す**。説明文だけ `GET /api/rules/{ruleId}` の応答で後追いに差し込む。
- 取得に失敗したら「説明を読み込めませんでした」+ 再試行ボタン。名前と効果文は出たまま残す。
- 「図鑑でくわしく」リンクは置かない。詳細モーダルが図鑑と同じ説明文を出すので、対局中に画面を離れる導線を残す理由がない。

### 2.3 有効ルール一覧モーダル

AppBar の「有効ルール N」(対局中)と待機画面の「有効ルール N」から開く。

- 内容は現行 `ActiveRulesScreen` と同じ(件数キャプション + 名前のみのリスト)。人気度・都道府県・優先度の数値は出さない(企画書 §4.5)。
- 行をタップすると §2.2 の詳細モーダルへ。
- 「図鑑でくわしく」リンクはモーダルからは外す(理由は §2.2 と同じ)。ルール図鑑はメニューから開く。

### 2.4 土台とルーティング

- 既存の `Dialog` に `onClose` を足して使い回す(閉じるボタン・スクリムのタップ・Esc)。新しいモーダル部品は作らない。
- 一覧モーダルは現行の `/rooms/:id/rules` をそのまま使い、**画面を差し替える代わりに `GameScreen` / `WaitingRoomScreen` の上に重ねる**。
- 詳細モーダルは `/rooms/:id/rules/{ruleId}` を新設して URL 同期する。同期しないと Android の戻るがモーダルではなく部屋を抜けてしまう。
- `parseRoomRoute` は `rules` の後ろに省略可能な `ruleId` を取れるようにする。`screenFromPathname` の対応は今までどおり `activeRules`。

## 3. 自分の手番(案 C)

`HandTray` に `isMyTurn` と `turnDeadlineAt` を渡し、トレイ自身が手番の状態を持つ。

### 3.1 見た目

| | 相手の番 | 自分の番 |
|---|---|---|
| トレイ面 | `--color-navy-100` | `--color-bg-surface`(白) |
| 枠 | `--border-control` / `--color-border-control` | `--border-heavy` / `--color-gold-400` + 外側に navy の輪 |
| 影 | なし | `--shadow-hard-m` |
| ヘッダ行 | なし(高さは確保して跳ねさせない) | 「あなたの番」ピル(金地・navy 文字・navy 枠) + 残り時間バー |

### 3.2 設計判断

- **札の面は減光しない**。相手の番でも手を組み立てられるべきであり、文字を透過させないのは G-7(あがり席の減光の裁定)と揃う。沈めるのはトレイの面・枠・影だけとする。
- **残り時間バーを卓の下から手札トレイの中へ移し、自分の番のときだけ出す**。現状は誰の手番でも同じバーが出ており、「自分の番」の信号として働いていない。相手の番の残り時間は見えなくなるが、席側の手番ハイライトと「考え中…」で代替する。
- **常時点滅はしない**。手番が回ってきた瞬間だけ 1 回、トレイが 2px 持ち上がってピルが跳ねる。考えているあいだずっと動くのは邪魔である。
- `prefers-reduced-motion` では動きを止め、色と枠だけで表す。
- 色だけに頼らないよう「あなたの番」の文字を必ず添える(デザインシステムの状態表現の原則)。

## 4. 影響範囲

| 層 | 変更 |
|---|---|
| `packages/server` | `RuleCatalogService.detail` / `GET /api/rules/{ruleId}` の追加。`RuleCatalogRepository` は変更なし |
| `packages/core` | **契約変更なし**。`PlayerRoomView`・`RuleRef` はそのまま |
| `packages/web` | `App.tsx`(卓の保持・モーダルの重ね方・ルーティング)、`RuleCutIn`(一拍)、`Table`(保持モード対応)、`HandTray`(手番)、`GameScreen`(残り時間バーの移設)、`Dialog`(`onClose`)、`rules/client.ts`(`get`)。`ActiveRulesScreen` の中身はモーダルへ移す |

## 5. 受け入れ条件

1. 8 切りが発動したとき、出した札が卓に見えている状態でカットインが始まり、カットインが引いてから場が流れる。
2. 場を流さないルールの発動でも、カットインの一拍とスキップが今までどおり動く。
3. 対局中に発動チップをタップすると、盤面を離れずにそのルールの説明文つきモーダルが開く。説明文の取得に失敗しても名前は出る。
4. 対局中・待機中とも「有効ルール N」がモーダルで開き、行のタップで詳細モーダルへ進む。どちらも Android の戻るで閉じ、部屋を抜けない。
5. 自分の手番になると手札トレイが点灯し、「あなたの番」と残り時間バーが出る。相手の番では沈み、残り時間バーは出ない。相手の番でも自分の札は読める。
6. `prefers-reduced-motion` で、手番の立ち上がりと場の吸い込みが動かない。
